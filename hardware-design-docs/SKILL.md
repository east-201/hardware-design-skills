# 硬件设计文档管理

把可复核的设计结果写入项目 `docs/`，让文档服务于硬件设计。固定十二章，主题按需增减；不为目录齐全而制造空文档，不引入数据库、审批链或日常操作报告。

## 共同约定

- 先读项目约定和现有目录，检索相关主题再写。已有文件优先局部更新；不要默认重写正文或迁移工程源文件。
- 从用户当前已确认的信息开始，讨论中备选方案注明“候选”，未知参数写 TBD；不虚构电路、器件参数、仿真或实测结果。
- 业务目录与主题文件用中文（型号、PCB 等术语可保留）。`中文主题_YY_MM_DD.md` 的日期是首次创建日期；后续保持文件名与 `created`，实质修改时更新 `updated`。日期使用用户项目本地日期，不能照抄示例或主机错误时区。
- 重要需求给稳定编号；一项事实只有一个权威维护位置，其他文档链接引用。区分目标、计算、仿真、实测及各自条件。
- 新增、移动、归档、删除和状态变化后维护索引；普通修改只更新受影响条目。不要因使用模板自动批准设计。
- 图用于说明真实关系：架构/电源树用 flowchart，状态用 stateDiagram-v2，交互用 sequenceDiagram；简单表格足够时不用图。Mermaid 不能替代精确原理图与 PCB。

## 按任务展开

初次初始化或分类时读 [章节职责](references/hds-structure.md)；撰写需求、设计计算、图或测试时读 [技术写作](references/writing-guidelines.md)。模板在 [assets/templates](assets/templates)，按实际信息裁剪，不能原样留下占位内容。

| 工作方式 | 本次需要完成的结果 |
|---|---|
| 新项目初始化 | 创建十二章及十三个 README；只用已知信息写必要主题，未知内容不编造。 |
| 持续设计 | 找到已有主题，将确定结论、必要依据和相关约束局部写入；候选方案保持候选状态。 |
| 接管已有项目 | 先盘点可读资料和版本，引用源文件；建立文档映射后渐进整理，保留原始有效内容。 |
| 文档审查 | 先机械检查，再检查需求→设计→验证、参数来源、旧方案引用、关键风险；默认只报影响设计的重要问题。 |
| 工程变更 | 更新权威文档，沿引用检查接口、电源/热预算、PCB、保护和验证影响；必要时记录变更及重验范围。 |

接管、冲突、移动或归档时读 [生命周期规则](references/lifecycle-workflow.md)。需要理解裁剪来源时读 [资料依据](references/technical-evidence.md)，不必每次重读标准网站。

## 机械维护工具

从 skill 实际所在目录运行 `scripts/hds.py`（仅 Python 3.10+ 标准库）。`--root` 总是项目根目录；普通章节 README 的目标/准则/待办由 Codex 按项目维护。

```powershell
python <skill>/scripts/hds.py init --root <项目根目录> --project "项目名称" --date <本地YYYY-MM-DD>
python <skill>/scripts/hds.py new --root <项目根目录> --section 05 --title "隔离RS485模块设计" --purpose "说明隔离与收发器方案" --body-file <已有实质内容的UTF8正文文件> --date <本地YYYY-MM-DD>
python <skill>/scripts/hds.py sync --root <项目根目录>
python <skill>/scripts/hds.py check --root <项目根目录>
```

`init` 可重复执行，不覆盖已有 README；无受管标记的现有索引由 Codex 局部接入，不让脚本覆盖。`new` 遇同名主题会拒绝，先检索同义主题；改现有文档用文件编辑工具局部改写。`sync` 仅改 `hds:index` 标记内的表格，保留外部手写说明；无变化不写盘。新主题须有实质正文。

脚本检查命名、元数据、重复标题/ID、受管索引和常见本地 Markdown 链接，不验证电路、需求覆盖、远程链接或 Mermaid 渲染。遇检查失败先定位，不为了消除告警修改真实技术事实。

每次完成只简短告知改了哪些设计、影响范围、必要的 TBD/风险和验证情况。不得声称满足标准认证。没有实质性变更时不创建额外记录。
