# 十二章与裁剪

所有项目保留以下顺序及一级目录。每章都有 `README.md`（章节目标、范围与准则、实际子文档索引、关键待办、章节关系）；总入口是 `docs/README.md`。README 不代替主题正文。无适用设计时在章节 README 简述“暂不适用及原因”，无需空主题。

| 目录 | 职责与深度 | 避免重复 |
|---|---|---|
| 01_文档控制 | 简短记录项目标识、文档版本和重要修订；必要时建立一份修订记录 | 普通润色交给 Git；没有 Git 时重要变更仍要留简短历史 |
| 02_项目介绍与范围 | 背景、目标、使用场景与系统边界 | 不复制需求细表 |
| 03_系统需求 | 重点：需求原因、量化条件/边界、优先级、验收标准、实现链接 | 重要需求稳定编号，不把器件实现当成功能需求；用户硬性指定器件可列约束 |
| 04_系统架构 | 重点：方案比较与选择、模块、资源、供电/信号流、依赖和冲突 | 系统选择留此处，电路细节链接第05章 |
| 05_硬件详细设计 | 最详细：目标、要求、器件与替代、原理、公式、裕量、PCB约束、验证和数据手册 | 小模块合并紧密相关分析；复杂电源等可按独立问题拆分 |
| 06_接口规格 | 适度：连接器/引脚、方向、电压、时序、协议、边界条件 | 引脚表在此权威维护；原理解释链接05 |
| 07_PCB与机械设计 | 适度：叠层/阻抗依据、布局布线、隔离距离、尺寸/孔位/高度、制造约束 | 电路来源引用05，约束必须可用于布板 |
| 08_功耗与热分析 | 适度：模式、负载、效率、最坏条件、功率裕量、温升依据 | 参数引用权威器件/电路文档，预算表在此维护 |
| 09_可靠性与保护 | 默认简短：目标、故障行为、ESD/EMC/EFT条件、保护覆盖 | 保护电路原理仍在05；高风险项目可加深，不能因“简短”省略关键安全分析 |
| 10_设计验证 | 默认一张表：需求/项目、方法、条件、验收、状态/证据 | 实测要有板卡版本、仪器/设置、日期/记录；计划不能算通过 |
| 11_风险与未决问题 | 默认一张短表：问题、影响、措施、状态、关联 | 只记阻碍当前设计的事项；负责人/期限按需 |
| 12_附录与参考资料 | 简短索引：原理图、网表、PCB、BOM、手册、报告及版本 | 引用实际工程路径，不把大文件重复复制入docs |

主题只在有内容时创建；无需一开始创建追溯矩阵、接口文档、风险文档等全套文件。少量需求的设计/验证链接可直接留在需求表，复杂后再拆矩阵。章节完成情况由已知覆盖范围人工判断，文档数量不等于完成度。
